# Recovery and audit after the D: disk failure

Date: 2026-09-10

A disk failure destroyed `apps/web/`, `apps/studio/`, the specs for features 007–009, and most
of the recorded dataset. This file records what came back, what did not, and the state each
feature is in now. It is the reference the reconciliation notes in `specs/*/tasks.md` point at.

## Where the recovery came from

The git object store lost every commit after July 2026, so nothing about Studio or Web was
recoverable through git. The source was the Claude Code session transcripts under
`C:\Users\Usuario\.claude\projects\`, which live on another disk. Each file was rebuilt by
replaying, in timestamp order, the writes, edits and complete reads those transcripts record.
326 files came back that way, across `apps/web/`, `apps/studio/`, `tests/`, `scripts/` and the
three specs.

The branch `009-web-capture-mode` was recreated on `a60c368`, the last commit whose tree
survived intact.

## What could not be recovered

**The recorded dataset (resolved 2026-09-10).** The dataset was restored to 1378 samples across
18 poses. `scripts/export_web_exemplars.py` now builds a 574.1 KB bundle over 17 poses and 2333
hands, matching the size feature 007 recorded before the failure, and `scripts/export_web_
fixtures.py` regenerates the matcher fixtures with real probe cases. Both outputs are git-ignored
generated data, so a fresh checkout must run them before the application will start: without them
`config/session.json`'s `activePoseSet` names poses the bundle does not contain and the session
config fails to load. `domain_expansion` holds a single sample and stays excluded until it has at
least 20.

**Source files with no recoverable copy.** These were written before the earliest retained
transcript and appear in no session:

- `apps/web/test/domain/landmarks.test.ts` (feature 007, task T012)
- `apps/web/test/adapters/effect-lifecycle.test.ts`
- `apps/web/test/domain/default-experience-assets.test.ts`

`src/domain/landmarks/topology.ts` was in the same position and was rebuilt as a faithful port
of `apps/engine/models/topology.py`, which is its authoritative source. `test/support/hands.ts`
was rebuilt from the contract its callers assert.

**Binary assets.** `apps/web/assets/audio/burst.wav`, `flash.wav` and `wash.wav` (feature 007,
task T082). Text-based recovery cannot return them.

**Tooling configuration.** `.eslintrc.cjs`, `.prettierrc` and the ignore files were rewritten
rather than recovered, so the rule set is a reconstruction that the codebase satisfies, not the
original one. `package-lock.json` was regenerated by `npm install`.

## Two known test failures that are not data loss

`test/adapters/color-picker.test.ts` — "preserves the selected colour across a series of edits"
requires the hue re-derived from a hex value to survive an unrelated edit exactly. Eight-bit RGB
cannot carry hue at that precision: the value drifts by under one degree per conversion whatever
the implementation does. The round-trip bug the same file also covers was real and is fixed.

`test/adapters/editor-navigation.test.ts` — "Play Selected rebases the clip to zero" asserts
that the first frame of a previewed clip draws something. The clip it selects is a
`background_wash`, whose fade-in is at zero opacity on that exact frame, so the runtime
correctly emits nothing. Rebasing itself works and is covered elsewhere.

## Studio

`tests/studio/presentation/test_renderer_fidelity.py` fails on one assertion: the raw-frame
reference draws no pixel matching its exact colour, because it is a one-pixel antialiased line.
This is feature 006 and was outside this audit's scope; it is recorded here so it is not
mistaken for a recovery artefact.
